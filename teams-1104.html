3-2. ③ Agentic 이 어떻게 뒤집혔나

10/25 진단에 이렇게 적혀 있습니다.

③ Agentic 경험 4/10 — 배점이 제일 큰데 제일 약합니다. 검사기는 있는데 그 결과를 다음 행동에 쓰지 않습니다.

「스스로 찾아보기」가 이걸 뒤집었습니다. 공고 조건을 못 채우면 AI 가 스스로 찾아 나섭니다.

✗ Java 또는 Kotlin 및 Spring 기반으로 API 를 설계·구현해 본 경험
   찾아볼게요 — Spring·Java 학습 및 서버 관련 레포가 있습니다
   카드로 안 만든 후보 63개를 읽었어요
   GitHub 에서 'Spring' 로 내 커밋 0개를 찾았어요
   GitHub 에서 'Kotlin' 로 내 커밋 1개를 찾았어요
   GitHub 에서 'REST API' 로 내 커밋 1개를 찾았어요
   쓸 만한 자료를 찾지 못했어요.

AI 가 조건마다 검색어 3개를 스스로 만들어 GitHub 을 뒤집니다. 못 찾으면 정직하게 못 찾았다고 하고, 찾으면 "후보로 카드 만들기" 로 이어 줍니다. 최대 5개 조건까지만(예산).

5. 채점 방법

무엇을어떻게
코드팀마다 .py/.java/.kt/.ts 중 크기 상위 6파일(에이전트·LLM 경로 3배 가중)을 받아 읽음. 팀당 94KB~440KB
구조파일 트리 전체(24팀 합 27,000줄) — 테스트 · CI · 배포 · 문서 · 에이전트 · 평가 · 가드레일
배포curl 로 상태 코드 확인
에이전트선언형 도구(tools=) + 외부 호출(httpx·API) + 조회 함수 · 예산(max_*) · 분기 · 루프 · 그래프
① 문제·타겟체크리스트 6개 — 문제 정의 문서 · 설계 문서 · 서비스 설명 · 흐름도 · 화면 · ADR
기준점우리 팀을 직접 써 보고 매긴 실측 89점 에 척도를 맞춤 (환산 90, 오차 ±1)

이 점수가 못 보는 것

1다른 팀은 화면을 열어보지 않았습니다. 배포 상태 코드만 확인했습니다 — ② 는 불완전합니다
26파일은 전체가 아닙니다. 핵심 코드가 7번째 파일에 있는 팀은 손해를 봅니다
3버그를 못 봅니다. 화면이 멈추는지는 코드로 안 보입니다

그래서 1~3점 차이는 의미가 없고, 10점 이상 벌어진 구간만 읽으시면 됩니다.

6. 남은 이틀

24팀 중 우리 강점은 "빠진 칸이 없다" 입니다. 3·4·8위 팀이 전부 한 항목에서 24팀 최고인데 다른 한 곳이 비어 있고, 그 빈칸이 대부분 배포 입니다.
남은 이틀도 같은 자리에 쓰면 됩니다 — 더 만드는 게 아니라 보이게 하는 데.
