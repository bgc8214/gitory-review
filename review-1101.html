6. 질문 3 — 핵심 하나 vs 전체

하나로 좁히세요. 다만 "기능 하나" 가 아니라 "한 문장" 으로요.

흐름이 다섯 단계라 "핵심 기능이 뭐냐" 에 답이 어려운 게 맞습니다. 그런데 심사위원이 궁금한 건 기능 이름이 아니라 "이게 결국 뭘 해주는 거냐" 입니다.

이렇게 말하면
❌ 다 비중 두기"레포를 정리하고, 카드를 만들고, 매칭하고, 되묻고, 자소서를 씁니다"
→ 다섯 개를 다 기억 못 합니다. 아무것도 안 남습니다
❌ 기능 하나만"공고 매칭 서비스입니다"
→ 그럼 사람인과 뭐가 다르냐는 질문을 받습니다
✅ 한 문장"내 커밋에서 근거를 찾아, 그 공고에 맞춘 자소서 문장까지 만들어 줍니다"
→ 다섯 단계가 이 한 줄의 과정이 됩니다

그리고 한 줄기로 보여주세요. 같은 커밋 하나를 끝까지 따라가는 겁니다.

커밋fix: change to dockerfile — 이것만으론 아무 뜻도 없는 커밋
근거AI 가 diff 를 읽고 → "Procfile 과 Nixpacks 를 제거하고 Python 3.11 기반 Dockerfile 로…"
카드STAR 네 칸, 칸마다 근거 커밋 링크
공고"필수 4개 중 3개 맞아요 · Go 경험이 아직 없어요"
자소서그 모자란 조건이 질문이 되고, 답이 문장이 됨

이러면 "기능 5개" 가 아니라 "커밋 한 줄이 자소서 문장이 되는 과정" 하나로 들립니다. 기억에 남는 것도 이쪽입니다.

7. 질문 4 — 사람이 끼어드는 게 감점인가

감점 아닙니다. 다만 보여주는 순서가 전부입니다.

"사람이 끼어들지 않아도 핵심 시나리오를 끝까지 풀어내는가" 는 "사람을 아예 안 쓰는가" 가 아니라 "사람이 없으면 멈춰 버리는가" 를 묻는 겁니다.

이렇게 보이면
감점AI 가 할 수 있는데도 사람에게 떠넘김 — "후보 66개 중에 고르세요"
가점AI 가 할 수 없는 걸 알아채고 묻기 — "이 10초는 커밋에 없는데 어디서 재셨나요?"

지금 네 개를 이 기준으로 보면

사람이 하는 일판정
후보 고르기괜찮습니다 — 66개 중 "먼저 카드로 만들어 볼 경험 5개" 를 AI 가 이미 추렸고, 어느 경험을 쓸지는 원래 본인만 압니다
되묻기 답변가점 쪽입니다. 커밋에 없는 수치는 사람만 압니다. "AI 가 모르는 걸 알아챘다" 로 읽힙니다
카드 확정이미 문제 없는 카드는 자동 확정됩니다(#584). 확인이 필요한 것만 남습니다
자소서 문항 입력중립 — 회사마다 문항이 달라 사람이 넣는 게 자연스럽습니다. 다만 "자주 나오는 문항" 버튼이 있으니 시연에선 그걸 눌러 1초에 끝내세요

시연 방향 — 제안하신 대로가 맞습니다. 하나만 바꾸면

"스스로 찾아 묻는 장면" 은 되묻기가 아니라 스스로 찾아보기 입니다.

되묻기는 "모르니까 사람에게 묻는" 장면이고, 스스로 찾아보기 은 "모르는 걸 알아채고 → 후보 63개를 뒤지고 → GitHub 까지 검색하고 → 그래도 없으면 없다고 말하는" 장면입니다. 묻기 전에 스스로 할 수 있는 걸 다 해 본 쪽이 훨씬 셉니다.

1사람 없이 도는 구간을 길게 — 분석 → 후보 추리기 → 카드 초안 → 검사·고쳐쓰기 (배속)
2스스로 찾아보기 을 제일 크게 — "GitHub 에서 'Spring' 로 내 커밋 0개를 찾았어요" 가 읽히게
3되묻기는 짧게 — "여기만 사람이 아는 것이라 묻습니다" 한 마디

말로 덧붙이실 거면 이 한 줄이면 충분합니다 — "사람을 덜 쓰려고 만든 게 아니라, 사람이 꼭 필요한 데만 쓰려고 만들었습니다."
